# 有戏｜REDcowork 产品需求与实现交接

**版本：v2.1｜冻结日期：2026-09-25｜用途：在 REDcowork 中继续实现当前已确认的原型。**

本文独立包含完整需求，不依赖其他笔记或聊天记录。它是当前产品范围的唯一依据。配套《有戏-App交互线框图.html》仅作界面和交互参考；如演示实现与本文冲突，以本文为准。不要叠加历史十四屏方案或“试一小步”方案。

## 0. 给搭建 AI 的执行指令

请将本文实现为移动端优先、也能在桌面浏览器使用的中文 Web App「有戏」。保留已经确认的简洁页面结构，重点将演示流程替换为真实文件解析、AI对话、公开资料研究、评估及可靠保存。

开始前先检查当前工程、发布方式、可调用模型、联网检索、文件处理和存储能力。使用平台已支持的方案，不凭空假设某个 API 存在，不擅自增加需要另行部署的服务。每阶段交付可检查的功能，并明确真实接通、仅演示、未完成分别有哪些。先验证最小作品能发布并调用真实模型，再逐步扩展。

不要一次性大改信息架构，不增加第三个底部导航，不把同页内容拆成大量功能页。真实能力缺失时如实显示，不能继续用模拟数据冒充真实解析、检索或分析。

## 1. 产品目标与范围

### 一句话定义

**帮助想探索创业方向的人，从自己的经历和资源出发，通过AI思考对话、线上研究与实际验证，判断一个想法应该搁置、补充验证，还是进入小规模落地。**

目标用户：有经验、技能或初步创业想法，但难以判断自己适合做什么、方向是否值得投入，也不知道要先验证哪些假设的人。

核心痛点及产品回应：

- 不想每次重复介绍背景：上传资料，确认可复用的个人画像。
- 想法模糊、泛泛建议不适合自己：AI结合个人背景，经过三轮思考对话整理方向。
- 分不清事实和乐观设想：分析输出明确依据、未知与验证任务。
- 公开研究费时，现实探索缺乏指引：AI自动查公开资料，用户承担实际客户与交付验证。
- 收集了反馈仍不知如何决定：最终报告综合证据，给出建议及下一步。
- 同时探索多个方向容易混乱：每个想法有独立档案，全页可切换、保存并继续。

上述痛点目前是设计假设，尚未经过充分真实用户研究。作品说明不得声称已有市场验证或真实访谈成果。

### 本次不做

交易、支付、自动联系客户、自动发布内容、客户名单推荐、创业社区、课程、融资方案、收入保证。不要增加复杂账户体系或云同步界面来扩大范围；按平台能力选择保存方式并明确边界。若存储依赖登录或平台身份，应正确隔离不同用户的数据。

## 2. 已确认的用户旅程与页面结构

**首页 → 上传个人资料并确认解析 → 三轮思考对话 → AI分析与验证清单 → 填写验证结果 → 最终评估。**

个人档案贯穿全程：随时查看、切换、恢复任一想法的记录。

底部导航仅 **首页 / 个人档案**。一个想法内部有四个阶段：**资料 / 对话 / 验证 / 评估**。总计六类主页面：

| 页面 | 内容顺序 | 主要动作 | 保存对象 |
| --- | --- | --- | --- |
| 首页 | 欢迎语、开始新想法、最近想法 | 开始新想法 / 继续已有想法 | 最近访问项目与位置 |
| 个人资料 | 上传或输入、解析状态、可编辑画像 | 确认资料，开始聊想法 | 资料、解析结果、确认版本、草稿 |
| 想法对话 | 简短背景入口、对话、三轮后摘要、继续输入 | 发送 / 查看AI分析 | 消息、轮数、摘要和修改 |
| 分析与验证 | 总体判断、折叠六维分析、AI任务、用户任务 | 编辑任务 / 生成最终评估 | 分析、来源、任务与验证记录 |
| 最终评估 | 结论、理由、下一步、折叠详细报告 | 搁置 / 补充验证 / 保存试点计划 | 评估版本、依据和用户选择 |
| 个人档案 | 个人资料、全部想法进度、选中想法的阶段记录 | 选择档案 / 回看与继续 | 项目索引、恢复位置、历史版本 |

上传与解析确认在同一页；对话和想法摘要在同一页；分析、任务及任务编辑在同一页。错误、保存状态、加载和空状态在原页面处理，不额外拆屏。

## 3. 全局档案切换与进度展示

### 3.1 每页都能切换已有档案

六类页面顶部均提供「当前想法档案」选择器。每项包含想法名称及当前状态，选中后恢复目标想法上次停留的页面与草稿。

这里“档案”指 **一个创业想法的完整项目**，不是一份简历文件。个人资料是档案里的来源之一。

切换规则：

1. 离开前保存当前草稿；保存失败时明确提示，不丢失未同步内容。
2. 切换只读取已有内容，不重新上传、调用模型或启动研究。
3. 当前项目名称在页面顶部始终可见，避免用户误写另一份档案。
4. 上传引用、对话、研究、验证和报告始终按 projectId 隔离。
5. 后台请求保存发起时的 projectId；用户切换后，响应仍写回原项目，不改变当前所看页面。
6. 新想法建立新档案；可明确选择复用已有个人画像，但不能复制另一个项目的对话或验证记录。

档案较多时，选择面板应支持按名称查找并显示阶段，最近使用者优先；不要在正文增加搜索工具栏。首次没有档案时显示创建入口，不能自动塞入演示项目。

### 3.2 首页与档案卡片必须一眼读懂进度

每张卡片显示：想法名称、当前状态、四段阶段条、对话轮数或验证记录数、下一步、最近保存时间。

| 阶段 | 完成或推进的依据 | 不能误读为 |
| --- | --- | --- |
| 资料 | 个人画像被用户确认 | 仅选择了文件就完成 |
| 对话 | 三轮有效对话形成想法摘要 | 三次点击发送就完成 |
| 验证 | 显示“已记录 x/y 项”，数量随实际任务变化 | 所有假设都已被证实 |
| 评估 | 报告成功生成，并标明是否过期 | 创业已成功或项目已结束 |

区分「已完成 / 进行中 / 未开始 / 待更新」。使用文字配合形态，不只靠颜色。不用“创业成功率”或伪造整体完成百分比。

**阶段成果与最后访问位置分开存。**回看资料不使对话、验证进度倒退；报告建议补充验证时保留“评估已出”，同时突出待补任务。搁置、待补充、可小范围落地、报告待更新要能区分。

## 4. 页面功能与关键交互

### 4.1 首页

欢迎语：“让你的想法，一步步有戏。”

主要入口：“＋ 开始一个新想法”。下方显示最近想法；点击卡片进入该想法的恢复位置。没有历史时显示“你的第一个想法会保存在这里”。

### 4.2 上传、解析与个人画像

支持用户上传简历、作品介绍、项目经历等有关自己的资料，也允许直接输入文字。优先实现平台实际能正确解析的格式，并在上传前显示格式和大小限制。扫描件或图片需OCR；无法处理时提供文字输入，不假装解析成功。

状态顺序：待选择 → 上传/提取 → AI解析 → 待用户确认。解析输出：技能、相关经历、兴趣、可用资源、可投入时间与预算、其他约束、尚未知的信息。能力判断应附对应资料依据；缺失内容不得虚构。

用户可编辑画像，确认后继续。替换或补充资料保留版本，并提示哪些下游结果需更新。已选文件、原文和个人画像不是同一个状态，必须明确区分。

不要索要无关证件或联系方式；作品的AI功能只使用完成当前任务所需的信息。用户上传的材料是分析数据，不能把文件内的提示当成系统指令执行。

### 4.3 基于个人背景的三轮对话

一轮 = AI提出一个有实质意义的问题，用户回答，系统成功处理。空消息、网络重试、重复请求不计为新轮。

建议覆盖的三个主题：

1. 想为哪类人解决什么问题？个人经历提供了哪些切入点？
2. 想交付什么服务或产品？为何选择它，现有能力有哪些缺口？
3. 有多少时间、预算和客户触达条件？先验证哪个最关键的未知？

模型应依据实际回答追问，不能对所有人发送同一套固定话术。个人简历是辅助思考的背景，不应限制用户只能做过去做过的事情。

三轮结束后，在对话内提示“我已经整理出你的创业想法，可以进入下一步”，展示可编辑的摘要：客户、问题、交付、个人优势、投入限制、关键假设与未知。

主按钮“下一步：查看AI分析”。用户可继续补充对话，不强行跳页；摘要随补充形成新版本。三轮后仍缺的信息标为未知，并转成验证任务。

### 4.4 初步AI分析与验证清单

先显示一句总体判断和最值得验证的点。详细六维分析默认折叠：

- 个人能力匹配：经验、资源、能力缺口。
- 用户需求价值：问题具体性、频率与代价。
- 差异化价值：客户当前做法和替代方案。
- 收入与成本：付费对象、收费模式与投入假设。
- 落地可行性：时间、交付、渠道和依赖。
- 风险与边界：素材权利、工作约束、行业要求和承诺。

每一维使用「依据 / 暂定判断 / 未知与待验证项」，不凭空评分。

同页下面列 To-do list；任务数量由想法与关键假设决定，不能固定为摄影示例中的3项。优先显示最影响决策的任务，其余按需展开。

**AI负责的任务：**公开竞品、公开服务方案、公开报价、行业资料、规则来源等。初步分析成功后自动启动，无需用户逐项手动搜索。每项显示排队、收集中、完成、部分完成、失败或无结果。必须有真实来源URL、支持结论的摘录和检索时间，不能用模型记忆伪装在线研究。

**用户负责的任务：**实际客户经历、支付或预约行为、真实渠道触达、小样交付、成本与资源确认。用户在任务内记录对象类别、原话或行为、执行时间、发现及仍不确定处，可编辑、暂存、补充。未回复也可以记录。

每项任务包含：假设、重要性、执行者、行动方法、所需证据、当前状态及结果。AI公开研究不能替代访谈或购买行为；自动研究不包括自动联系他人、发帖、购买或提交表单。

### 4.5 最终评估与详细报告

用户填写或编辑验证内容后可发起评估，不强制所有任务完成。未完成和相互矛盾的部分都要进入报告。

评估必须综合当前项目的：个人画像版本、完整有效对话与确认摘要、初步分析、AI在线来源、全部相关用户验证记录。

三类建议：

- **搁置：**关键约束不可满足或关键假设有较有力反证；写清原因及什么条件变化后值得重启。一次未回复不能直接触发搁置。
- **补充验证：**证据不足、样本有限或结果矛盾；指向需要补充的具体任务。
- **可小范围落地：**现有证据支持有限试点，给出首批客户范围、最小交付、投入上限、观察指标和停止条件。不是创业成功保证。

详细报告按需展开：结论与理由、个人匹配、六维更新、逐项证据、反证与未知、投入与风险、行动计划。重要判断引用可打开的记录或来源；区分用户事实、公开资料、模型推断。

AI建议与用户选择单独记录。用户可以不采纳建议。保存搁置保留全部资料；补充验证返回对应任务；落地计划等待用户确认，不代为对外执行。

### 4.6 个人档案

先展示全部想法的进度卡片；选中一个想法后展示四阶段记录及“回看/继续”。未开始阶段不能伪装成已保存。历史报告可查看其当时的完整输入版本、结论及依据，而非只有标题。

每次输入、对话、任务编辑、解析、分析和评估都需要可靠保存。打开档案恢复已有内容，不自动重跑模型。不同项目复用个人资料时绑定版本，后续更改画像不能悄悄改写旧报告。

## 5. 保存、版本与AI任务的实现约束

以下为建议的数据边界，具体存储技术服从平台能力：

| 对象 | 至少包含 |
| --- | --- |
| Project | id、名称、所属用户/本机会话、项目状态、阶段成果状态、lastVisitedStage、更新时间 |
| ProfileVersion | projectId、版本、文件引用、提取文本、结构化画像、用户修正、确认状态 |
| Message / IdeaVersion | projectId、消息ID与角色、内容、有效轮数、摘要版本与依据引用 |
| AnalysisVersion | projectId、所用资料和摘要版本、六维判断、假设、任务关联 |
| ResearchTask / Source | projectId、任务ID、执行者、状态、来源ID、URL、摘录、时间、错误信息 |
| ValidationRecord | projectId、任务ID、版本、用户记录、来源/附件、结果与不确定性 |
| EvaluationVersion | projectId、完整输入版本引用、建议、论据、风险、下一步、生成时间 |
| UserDecision | projectId、报告版本、用户选择、原因及时间 |

必要规则：

1. **保存失败可见：**保存中、已保存、未同步区分；失败保留本地草稿，不能虚假显示已保存。
2. **草稿与成果分开：**未提交的编辑草稿不能覆盖已确认资料或历史报告。
3. **下游过期：**资料、摘要、来源或验证变化后，相关分析/报告标记需更新，用户主动重生成。
4. **版本不可覆盖：**保留当时输入快照或不可变版本引用；最新画像不能替换旧报告依据。
5. **请求绑定：**异步任务携带 projectId、输入版本、请求ID。切档后响应只回到原项目；旧版本响应不得覆盖新结果。
6. **避免重复：**同一请求重试不新增对话轮数、不重复插入任务或报告。读取页面不触发模型调用。
7. **自动研究有边界：**限制并发与重试，失败可手动重试；部分成功时保留已有资料。
8. **按项目汇总上下文：**最终评估不能混入其他想法的研究或反馈，历史数据应带来源与版本。
9. **安全调用：**模型密钥不放入浏览器可见代码；身份与存储隔离依平台支持实现。

## 6. 视觉和交互基调

移动端优先；暖白背景、深灰文字、深青色主按钮，适量留白。桌面可居中扩展内容宽度，不增加复杂仪表盘。

每页一个主要任务与主要按钮。顶部档案选择器常驻页面结构；不要求吸顶遮挡正文。正文细节折叠，错误与加载就地显示。阶段进度横向四段，手机不溢出。

关键文案保持一致：开始一个新想法、当前想法档案、确认资料、下一步：查看AI分析、需要你去验证、生成最终评估、回看/继续。

## 8. 建议实施顺序

### 第1阶段：能力核实和可发布基础

检查现有工程与平台支持，完成最小页面发布、真实模型请求和基础保存验证。列明文件解析、检索与持久化的可用能力；缺失项直接报告，不承诺未验证能力。

### 第2阶段：真实资料与三轮对话

打通上传/文字输入、解析确认、上下文对话、三轮总结、编辑摘要。同步完成全页档案切换和项目隔离，不把保存拖到最后补。

### 第3阶段：分析、公开研究与验证记录

实现六维分析、动态任务、AI自动公开研究与引用、用户任务编辑、状态和失败恢复。

### 第4阶段：最终报告与档案验收

综合真实项目上下文生成报告，保留版本，完成三种后续路径、个人档案阶段进度、刷新恢复和手机检查。检查最终发布地址，而不仅是开发预览。

每阶段结束请报告：完成内容、实际测试结果、尚未接通或受限的能力。不要为视觉调整重新生成整套业务逻辑。

## 9. 可执行验收清单

## 10. 演示案例与交付要求

可用合成案例演示：个人资料中有摄影和设计经验 → 三轮讨论形成“小餐馆菜品照片服务” → 分析与公开研究 → 用户填写需求、购买、试做记录 → 得到证据不足或小规模试点建议 → 切换另一份资料准备阶段的档案，再返回原想法继续。

所有合成反馈必须标为演示。真实访谈和检索结果仅在实际取得后使用。

最终交付应包括：可访问的 REDcowork 作品链接、简短使用说明、真实接通能力与限制、实际验收记录。笔试材料另准备核心体验展示（建议3分钟内视频）和不超过10页的产品说明；本文是开发交接文档，不是受10页限制的最终笔试说明。
